# 隐私设计

> 一句话：**能唯一定位到某个人的信息，一步都不出本机。**

---

## 一、PII 的判定标准

这个工具用一条清晰的标准判断「什么算敏感信息」：

> **单条信息能否唯一定位到现实中的某个人？**

| 字段 | 算 PII？ | 理由 |
|---|---|---|
| 姓名、手机号、身份证号、电子邮箱 | ✅ 能 | 单独一条就能定位到人 |
| 通讯地址、户籍所在地、精确出生日期 | ✅ 能 | 结合公开信息可定位 |
| 紧急联系人姓名 / 电话 | ✅ 能 | 指向第三方，同样敏感 |
| **性别 = 男** | ❌ **不能** | 有数亿人是「男」 |
| **政治面貌 = 党员** | ❌ **不能** | 有上千万人是党员 |
| **最高学历 = 硕士研究生** | ❌ **不能** | 无法定位 |
| **手中的证书、技能、经历正文** | ❌ **不能** | 内容本身不指向特定人 |

### 为什么这条标准很重要

如果采用「**所有字段一律打码**」的粗暴做法，会出现两个后果：

1. **文本变得不可用**。「【性别】、【政治面貌】、【学历】」——AI 拿到的
   是一堆占位符，写不出任何有意义的内容
2. **安全性的假象**。把 `性别=男` 当成机密，等于对外宣称
   「不脱敏就会泄露你」，这会让用户的信任建立在错误认知上

所以本工具采用**白名单**：只脱敏真正能定位到人的字段。

## 二、三条红线的技术实现

### 红线 1：不代提交

- `fill_form.py` 的 `apply_plan()` **只处理输入控件**，代码里没有任何
  `click` 提交类按钮的分支
- 扫描阶段就排除了 `type=submit` / `type=button` / `type=reset`
- 程序填完后打印「⚠️ 已停在提交前」，然后退出

### 红线 2：不碰凭据

三类控件被统一归入**人工门**，无论能否映射到档案键，程序都不写入：

| 类型 | 判定 |
|---|---|
| `type=password` | 直接判为人工门 |
| 标签含「验证码 / captcha / 短信验证 / 动态码」 | 判为疑似验证码 |
| `type=file` | 附件上传，需要人从本机选文件 |

人工门会出现在报告的 `人工门` 数组里，附原因说明。

### 红线 3：值不出本机

这是最需要小心的一条，因为它很容易被**无意中**破坏。

**反面写法（已避免）**：
```python
print("填入了：", value)        # ❌ 值进了终端 → 进了 AI 上下文
logging.info("profile=%s", profile)   # ❌ 值进了日志文件
```

**本工具的做法**：
```python
# fill_form.py —— 只打印状态，不打印值
print("[4/5] 写入表单（不提交）")
print("      已填 %d ／ 失败 %d ／ 跳过 %d" % (...))

# make_sheet.py —— 值只写进文件
with open(out, "w", encoding="utf-8") as f:
    f.write(content)      # 值在这里落地，但不经过 stdout
```

**自测里的反证用例**（`tests/test_core.py`）：
```python
def test_report_no_values(self):
    """体检报告结构里不能夹带真实值"""
    rpt = core.profile_report(self.profile, self.fields)
    blob = str(rpt)
    for v in self.profile.values():
        if isinstance(v, str) and len(v) >= 6:
            self.assertNotIn(v, blob, "体检结果里泄漏了真实值：%s" % v)
```

这条测试会在你（或未来的贡献者）不小心往报告里塞真值时**直接失败**。

## 三、脱敏通道的工作方式

```
原稿.txt
   │
   ├─ 1. 白名单过滤：只取 PII_KEYS 里的字段，且值长度 ≥ 2
   │
   ├─ 2. 长值优先替换（避免子串误伤，如「张三」与「张三丰」）
   │      张三 → 【姓名】
   │
   ├─ 3. 二验：再扫一遍，确认真值无残留
   │      有残留 → 拒绝输出，返回码 1
   │
   └─ 4. 输出脱敏稿.txt（映射表只在内存，用完即弃）
```

**还原**是反向操作：把 `【姓名】` 换回真值。映射表每次都从档案现算，
**不落盘**。

> ⚠️ 注意：这是一道「**防止无意泄露**」的闸，不是加密。
> 脱敏稿仍然能被读过档案的人还原 —— 它保护的是「发给第三方 AI 的那一段文本」。

## 四、你的档案放在哪

- **位置**：你指定的路径（建议项目根目录 `profile.json`）
- **版本控制**：`.gitignore` 已屏蔽 `profile.json` 及相关模式
- **网络**：程序**从不**对档案发起任何网络请求
- **AI**：档案内容**从不**进入 AI 上下文

**唯一读取档案的地方**是：`check_profile.py`（只读字段名做体检）、
`fill_form.py`（取值直写浏览器）、`make_sheet.py`（取值写本地文件）、
`mask_pii.py`（取值做替换）。四处都不打印值。

## 六、已知边界

本工具**不做**这些事，请知悉：

- 不加密档案文件（它就是明文 JSON，靠文件系统权限保护）
- 不防止本机其他程序读取档案
- 不校验你填进去的信息是否真实
- 不保证目标网站不会记录你填的内容

它保护的是「**你的信息不因使用本工具而多一次外流**」。
